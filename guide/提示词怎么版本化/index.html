提示词怎么版本化How to Version Your Prompts

微型指南 · 约 6 分钟Guide · about 6 min · 引用核验 2026-11-03（仅引用链接与日期） · refs checked 2026-11-03 (reference links and dates only)

线上效果说不清是哪次改动带来的，多半因为提示词散在代码里随手改。这篇讲把提示词当代码管的最小做法。If you can't say which change moved your live numbers, it's usually because prompts live inside code and get edited on the fly. The minimal way to treat prompts like code.

怎么做How to

提示词从代码字符串里拆出来单独存放：改提示词不该触发重新编译或部署。

每次改动进版本控制并写清动机：和代码一样可回溯、可对比、可回滚。

改动配回归：跑一套固定输入对比新旧输出，没有评测就谈不上「改好了」。

记录提示词与模型版本的配对：同一提示词换模型可能失效，两者要一起记。

线上出问题时先查提示词变更记录：它和代码一样是常见变更源，却常不在审计范围里。

A/B 对比要控制变量：同时换提示词和模型，就难以区分两者各自的影响。

Move prompts out of code strings into their own files: editing a prompt shouldn't require a rebuild or redeploy.

Commit every change with the motivation written down: traceable, diffable, revertable — just like code.

Pair changes with a regression run: fixed inputs, old vs new outputs; without an eval, "improved" is a feeling.

Record prompt and model version as a pair: the same prompt can break on a new model; log them together.

When production misbehaves, check the prompt changelog first: prompts are a common change source that rarely sits inside the audit trail.

Control variables in A/B comparisons: swap prompt and model together and you'll never know which one did it.

例子与判断Example and interpretation

以下是教学情境，不是本站运行或实测记录。A teaching scenario, not a measured or executed site test.

保留 v1 和 v2 两份提示词，记录本次只改了“缺失信息写未知”。在同一组材料、同一模型设置下对比是否减少补写，再记录退化样本。不要同时换模型后把全部差异归因于提示词。Keep v1 and v2, recording one change: mark missing information unknown. Compare the same inputs and model settings, checking invented details and regressions. Do not change the model simultaneously and attribute every difference to the prompt.
