加了护栏就安全了Guardrails Make It Safe

微型指南 · 约 5 分钟Guide · about 5 min · 引用核验 2026-11-06（仅引用链接与日期） · refs checked 2026-11-06 (reference links and dates only)

护栏改变的是默认路径，不是所有路径。Guardrails change the default path, not every path.

接上厂商的护栏，系统就安全了。Turn on the vendor's guardrails and the system is safe.

护栏拦的主要是训练与部署阶段预期内的常见路径。绕开它的内容（改写措辞的诱导、藏在工具返回或网页正文里的指令），以及护栏自己的边界，仍要靠你的权限设计、出口校验和事件流程。判断护栏有没有生效，要做一次能复现的检查（虚构示例）：输入一段带指令的不可信文本 → 处理是按真实链路走一遍 → 结果判断看它是否执行了那条指令或读出了环境变量 → 若执行了，下一步是收紧工具权限并在出口加过滤，而不是把「护栏已开启」当成结论。Guardrails mainly cover common paths anticipated during training and deployment. Content routed around them - reworded inducements, instructions hidden in tool output or web page text - plus the guardrails' own boundaries still depend on your permission design, exit validation and incident process. Verifying that guardrails actually work means a reproducible check (fictional example): input an untrusted text carrying an instruction -> processing runs it through the real chain -> the check looks at whether that instruction executed or environment variables were read -> if it executed, the next step is to tighten tool permissions and add exit filtering, not to treat "guardrails enabled" as the conclusion.

演示一次绕过：给分类器喂一段带诱导指令的输入，看它是拦截、降级还是照常输出。护栏是概率性防护，验证报告要写清测了哪些类别、没测什么。Run one bypass demo: feed the classifier an input carrying an overriding instruction and see whether it blocks, degrades or answers anyway.
