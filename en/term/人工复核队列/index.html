Human Review Queue

Human Review Queue

  • Agents
  • Stage 3 · Going Deeper
  • refs checked 2026-11-06
What problem it solves

How the cases a classifier cannot settle get queued for a person, and where the human verdict goes afterwards.

What it is
There are two queues: content pulled aside for review, and actions waiting for approval before they run. Microsoft Agent Framework implements the second with a request-and-response mechanism — execution reaches a request port, pauses, emits a request event, and only continues when an outside reply arrives; tool calls that need approval follow the same path. A pause has to be resumable. The same document states that pending requests are saved as part of a checkpoint and are re-emitted when the run is restored, which means the queue cannot live in memory alone: after a restart it still has to know who is waiting on whom. Roblox's creator documentation shows the first kind. Assets get both human and automated moderation, proactively and reactively, and an asset still sitting in the moderation queue stays invisible to users until it is approved. The queue itself needs measuring: how long items wait, what share of machine flags hold up, how often a reviewer overturns one, and how those verdicts feed back into the threshold. There is no published standard here, so you define it and keep the records — otherwise you cannot tell improvement from merely being busy.
Why it matters

Adding human review is the easiest line in a spec and the hardest thing to run: backlog, permissions, review records and conclusions that flow back. Settling those four first keeps the queue from becoming the step nobody owns.
