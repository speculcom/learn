How to Acceptance-Test a Multimodal Model

Guide · about 8 min · refs checked 2026-11-19 (reference links and dates only)

A pretty answer about an image does not mean it works. Acceptance testing separates seeing, understanding and acting on it.

How to
Build three sets: pure recognition (OCR, objects, chart reading), relational reasoning (comparison, cause, space), and task execution (edit code from an image, fill a form, navigate). Keep the original image and the reference answer for every item; require the model to cite coordinates or regions. If it cannot, count it as a lucky guess. Add adversarial samples: blur, rotation, occlusion, typos, misleading charts; see whether it admits it cannot see. Test description and decision separately: a correct description with a wrong action means the vision-to-action path is not connected. Record token cost: image tokenisation is expensive, and long or multiple images raise the unit price sharply. Compare against at least one baseline on the same set; without a baseline there is no “good”.

Example and interpretation

A teaching scenario, not a measured or executed site test.

Give the model a financial table screenshot with small text and a legend, ask for three numbers plus their bounding regions. Rotate the image 15 degrees and occlude part of it; a usable chart reader must say what it cannot see. Pass both to qualify.

How to check your practice

Explain the example in your own words, inspect input constraints, then verify against the source. Revisit concepts if you cannot explain why; supply missing dates, fields or permissions; withdraw unsupported conclusions.
