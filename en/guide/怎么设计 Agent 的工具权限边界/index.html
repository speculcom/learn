How to Set Tool Permissions for an Agent

Guide · about 8 min · refs checked 2026-11-17 (reference links and dates only)

The risk of an agent is not a wrong sentence; it is pressing an irreversible button on your behalf. Classify permissions first, then narrow them.

How to
List every tool and classify it into five levels: read-only, write, external send, spend and delete. Default to least privilege: one directory, not the whole disk; query access, not write access. Require confirmation for writes: show the parameters and blast radius, then execute only after a human approves. Treat external send and payment separately: these are irreversible and need a human in the loop. Use allowlists, not blocklists: enumerate permitted URLs, commands and paths. Log every call: who, which parameters, result and latency; logs must replay to a specific task. Treat tool output as untrusted input, never execute instructions inside it, and run periodic privilege-escalation drills.

Example and interpretation

A teaching scenario, not a measured or executed site test.

Draw a permission matrix: every tool against read, write, send and pay actions, marked allow, confirm or deny. That table is the pre-launch review checklist.

How to check your practice

Explain the example in your own words, inspect input constraints, then verify against the source. Revisit concepts if you cannot explain why; supply missing dates, fields or permissions; withdraw unsupported conclusions.
