How to Read an Open-Model License

Guide · about 8 min · refs checked 2026-11-03 (reference links and dates only)

"Open source" does not mean use however you like. The conditions in a model license decide whether you may use it commercially, attribute, and what derivatives inherit.

How to
Separate open-source software licenses from model licenses: the latter often carry extra conditions you cannot infer from the words "open source". Check commercial terms: some licenses ban commercial use; others set a scale threshold. Check attribution: Apache 2.0 requires keeping notices and the NOTICE file. Check derivative duties: copyleft licenses require models you fine-tune to carry the same license. Check use restrictions: many model licenses forbid certain use cases; violating them voids the license. Check license inheritance: which license a fine-tuned, quantized, or merged model carries is recorded repo by repo in this site's model profiles.

Example and interpretation

A teaching scenario, not a measured or executed site test.

Open the actual repository's LICENSE and record version, attribution, redistribution and use restrictions. If a quantized repository links upstream terms, inspect both sets of notices rather than stopping at a sidebar label.

How to check your practice

Explain the example in your own words, inspect input constraints, then verify against the source. Revisit concepts if you cannot explain why; supply missing dates, fields or permissions; withdraw unsupported conclusions.
