AI Misconceptions: Index

Guide · about 6 min · refs checked 2026-11-03 (reference links and dates only)

An index of misconceptions — more parameters is smarter, bigger context is better, a high leaderboard score means usable — each pointing to its explanation.

How to
More parameters is smarter: scale interacts with data, architecture and task; a single number is not enough. Bigger context is better: context has VRAM and latency costs, and middle-of-input use is uneven. Higher temperature is smarter: temperature changes sampling randomness, not what the model knows. A high leaderboard score means usable: benchmarks have version, contamination and task-mismatch problems; run your own task set. Quantisation halves intelligence / not enough VRAM means it cannot run: quality depends on tier and calibration; low VRAM can use CPU offload, multi-GPU splitting or a smaller member. Open models are always cheaper / preview builds cannot be used in production: hardware, power, operations and time all count; check the specific product terms. API compatibility means behaviour matches / switching models is just a rename: protocol compatibility is not output semantics; prompts, tools and evals all need realignment.

Example and interpretation

A teaching scenario, not a measured or executed site test.

Write down three tasks before choosing a model. If your only evidence is parameter count, context size and ranking, revisit those misconceptions and add task conditions and usage cost.

How to check your practice

Explain the example in your own words, inspect input constraints, then verify against the source. Revisit concepts if you cannot explain why; supply missing dates, fields or permissions; withdraw unsupported conclusions.
