How to Run Cross-Model Regression Tests

Guide · about 9 min · refs checked 2026-11-17 (reference links and dates only)

A model upgrade is not just “a stronger model”. The same regression set must run before and after to separate capability changes from style changes.

How to
Fix a 50–100 case regression set covering common tasks, edge inputs and must-refuse scenarios. Write expected bullet points rather than one gold answer, and score coverage of those points. Run the same set before and after, recording pass rate, citation accuracy, refusal rate and average length. Report capability change and style change separately: longer or more polite is not better. Use model judging only for triage, with 20 percent human review to counter position and verbosity bias. Set a rollback threshold and use it; do not ship on “it feels better overall”. Keep every raw output, and count system-prompt, tool-description and retrieval-index changes as changes too.

Example and interpretation

A teaching scenario, not a measured or executed site test.

Build a 60-case regression set, 20 of which must be refused or answered with “I don’t know”. On a model upgrade, the pass rate on those 20 matters more than the total score.

How to check your practice

Explain the example in your own words, inspect input constraints, then verify against the source. Revisit concepts if you cannot explain why; supply missing dates, fields or permissions; withdraw unsupported conclusions.
