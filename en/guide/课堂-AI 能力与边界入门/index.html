Lesson - AI Capabilities and Limits

Lesson plan · about 12 min · refs checked 2026-11-07 (reference links and dates only)

The first micro-lesson turns what AI can do into a checkable task list. Learners separate fluent output from source-supported output and write down cases that need human fallback.

Lesson objectives
Rewrite a vague need into a task with inputs and completion criteria. Distinguish fluent output from source-supported output and give one classroom example of each. Name three kinds of content that need human review: numbers and dates, external facts, and decisions affecting people’s rights. Describe a result by scenario and multiple metrics rather than reporting only one total score.
Materials
Microsoft Learn module Introduction to generative AI and agents: read the LLM and prompt sections before class. HELM abstract page (arXiv 2211.09110): see why it evaluates by scenario and metric. One recording sheet per group with five columns: task, input material, model output, basis for judgment, items to recheck. Learners bring their own chat AI entry point; the class does not procure accounts or collect account information.
Steps
    2-minute opener: each group writes a real need, and the teacher rewrites it as input plus completion criteria. 4-minute demo: ask about the same material twice, once with only introduce this and once with fields and limits. 4-minute practice: groups fill the sheet and split claims into supported by the material and needing external checks. 2-minute wrap-up: each group reports one limit and one fallback action; the teacher groups them by scenario and metric.
Common misconceptions
Treating confident tone and complete structure as correctness; fluency is not evidence. Treating one total score or leaderboard rank as fit for every task; HELM measures seven metrics across scenarios. Treating the model saying it does not know as weakness; admitting unknown when input is missing or out of scope is usable behaviour.
Assessment checks
The task includes input and completion criteria; if either is missing, return to the opener and rewrite. At least one claim is marked as needing external checking, with the source to be used named. Learners can state what this lesson did not do: only source and condition checks, no performance benchmark and no model ranking.

Example and interpretation

A teaching scenario, not a measured or executed site test.

Class exercise: rewrite introduce this notice into extract time, place and registration method; leave fields absent from the source empty. After output, link each field back to the source and mark fluent but unsupported fields for review.

How to check your practice

Explain the example in your own words, inspect input constraints, then verify against the source. Revisit concepts if you cannot explain why; supply missing dates, fields or permissions; withdraw unsupported conclusions.
