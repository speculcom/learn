运维上线路线The Operator's Route

落地Ship it部署、上线与团队决策Deploy, operate and decide for a team

约 60 分钟about 60 minutes

沿运行、监控、权限、故障与退役读十四个主题。先建立排查顺序，再用具体服务的配置与日志验证。Study fourteen topics covering runtime, monitoring, permissions, failure and retirement. Form an investigation order, then validate it against a service’s configuration and logs.

  1. 说出首字延迟和吞吐各自受什么影响，各给一个优化手段
  2. 给线上服务列出三件必须监控的事，并说明各自先查什么
  3. 供应商宣布模型退役时，能走一遍迁移评估的四个检查项
  4. KV 缓存为什么会占满显存，何时需要分页或量化？

  9. 服务中断时，先保什么、后保什么？
  10. 模型退役迁移，为什么先跑回滚再切换？

  2. List three things a live service must monitor, and what to check first for each
  3. When a vendor announces retirement, walk through the four migration-assessment checks
  4. Why does the KV cache fill memory, and when do you need paging or quantisation?

第 1 题 · 参考回答Question 1 · Reference answer

首字延迟影响开始等待的时间，吞吐影响连续生成或并发能力。前者可先查输入处理与排队，后者可查批处理与硬件瓶颈；需用相同负载验证。Time to first token affects initial waiting; throughput affects generation/concurrency capacity. Investigate input processing and queues for the former, batching and hardware limits for the latter under equal load.

第 2 题 · 参考回答Question 2 · Reference answer

先看任务完成率、延迟分布、错误、用量和权限异常。成本突增时对照请求数、输入长度、重试和工具调用记录，不立即归因于模型单价。Track completion, latency distribution, errors, usage and permission anomalies. For a cost spike, compare request count, input lengths, retries and tool calls before blaming the model rate.

第 3 题 · 参考回答Question 3 · Reference answer

至少覆盖接口与流式、任务质量、工具与权限、成本与延迟，并核对数据条款和回滚。先在代表性请求上对比，达到预先约定的条件再切换。Cover interface/streaming, task quality, tools/permissions and cost/latency, plus data terms and rollback. Compare representative requests before switching against agreed criteria.

第 4 题 · 参考回答Question 4 · Reference answer

每个并发请求都要为历史 token 保存键值向量，长度和并发上升时线性增长。并发高、上下文长或显存紧张时，分页、量化或缩短上下文才值得评估；先测命中率与延迟再选。Every concurrent request stores key/value vectors for prior tokens, growing linearly with length and concurrency. When concurrency, context or memory pressure is high, evaluate paging, quantisation or shorter context; measure hit rate and latency first.

回看这一题的概念Revisit this concept

第 5 题 · 参考回答Question 5 · Reference answer

新请求会插进正在生成的批次，单请求的首字与完成延迟可能变长，调度和显存管理更复杂。吞吐提升不等于每个用户都更快，要同时看 P50/P99。New requests join an in-flight batch, so per-request time-to-first-token and completion can stretch, and scheduling plus memory management get harder. Higher throughput is not faster for every user; watch P50 and P99.

回看这一题的概念Revisit this concept

第 6 题 · 参考回答Question 6 · Reference answer

至少按租户、密钥、请求数/分钟、token/分钟和并发数分开；再叠加工具调用与重试。只限请求数，长上下文请求仍可能拖垮成本与延迟。At least tenant, key, requests per minute, tokens per minute and concurrency; add tool calls and retries. Limiting request count alone still lets long-context calls wreck cost and latency.

回看这一题的概念Revisit this concept

第 7 题 · 参考回答Question 7 · Reference answer

异常的工具名/参数、检索内容触发外部 URL、权限被拒后反复重试、同一会话突然改变任务。日志要能关联输入来源、工具调用与授权结果，否则只能看到失败。Unusual tool names or arguments, retrieved text triggering external URLs, repeated retries after permission denials, or a session abruptly changing task. Logs must link input source, tool calls and authorisation outcomes, or you only see failure.

回看这一题的概念Revisit this concept

第 8 题 · 参考回答Question 8 · Reference answer

模型可见的工具清单、执行端的凭据与资源范围、数据层的行级/字段级访问。三层任一层放宽，模型提议就可能变成越权动作。The tool list visible to the model, credentials and resource scope at execution, and row/field access at the data layer. Loosen any layer and a model proposal can become an unauthorised action.

回看这一题的概念Revisit this concept

第 9 题 · 参考回答Question 9 · Reference answer

先保鉴权、审计与可回滚的核心读写，再保非关键生成与实验流量；先切断有外部副作用的工具，再降级为只读或排队。顺序要事先写成 runbook，而不是临时决定。Protect authentication, audit and rollback-critical reads/writes first, then non-critical generation and experiments; cut tools with external side effects, then degrade to read-only or queueing. Write the order into a runbook in advance.

回看这一题的概念Revisit this concept

第 10 题 · 参考回答Question 10 · Reference answer

新模型在接口、流式、工具调用和质量上都可能变；先证明能切回旧版本，再把流量按比例放大。没有回滚，一次切换失败就会变成全量事故。A new model can change interface, streaming, tool calls and quality; prove you can switch back before scaling traffic. Without rollback, one failed cutover becomes a full outage.

算显存、功耗与总成本Work out VRAM, power and total cost

先把硬件、云租用与电费放在同一张账上，再谈「值不值」。Put hardware, cloud rental and electricity on one bill before arguing whether it is worth it.
