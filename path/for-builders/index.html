动手开发者路线The Builder's Route

进阶Builder看得懂概念，开始动手做Know the basics and start building

约 60 分钟about 60 minutes

按搭建顺序读接口、检索、工具调用、评测与成本。阅读用于理解链路；实际接入还需按当前版本检查并验证。Study interfaces, retrieval, tools, evaluation and cost in build order. This explains the pipeline; actual integration still needs version checks and validation.

学完自测Checkpoint
  1. 说清一次 API 调用的费用由哪几段 token 构成
  2. 解释检索链路里分块与嵌入各自决定什么
  3. 指出接入工具调用时最先要设的两道防线
  4. OpenAI 兼容接口为什么能接多家模型？哪些地方仍会不同？
  5. 向量检索效果差，先查分块还是先换嵌入模型？给出排查顺序。
  6. 检索增强能解决什么，不能解决什么？
  7. 工具定义与工具调用分别由谁负责？
  8. MCP 主要解决接口标准化还是权限问题？
  9. 工作流编排与 Agent 自主决策的界线在哪里？
  10. 上线前的最小评测集，至少要有哪三类样本？
  1. Break down an API call's cost into its token segments
  2. Explain what chunking and embedding each determine in a retrieval pipeline
  3. Name the first two defenses to put in place when adding tool calling
  4. Why can an OpenAI-compatible API reach many models, and what still differs?
  5. Retrieval is weak: check chunking first or swap the embedding model? Give the order.
  6. What does retrieval augmentation solve, and what does it not?
  7. Who owns tool definition and who owns tool invocation?
  8. Does MCP mainly solve interface standardisation or permissions?
  9. Where is the line between workflow orchestration and agent autonomy?
  10. What three sample types should a minimum pre-launch evaluation set include?

第 1 题 · 参考回答Question 1 · Reference answer

输入包括指令、历史、检索材料和工具返回；输出是模型生成的内容。按各自用量乘相应单价，再核对缓存、工具与重试是否另计，不用一个总 Token 数乘同一单价。Input includes instructions, history, retrieved material and tool results; output is generated content. Apply the relevant rates and check cache, tool and retry charges separately. Do not assume one rate for every token.

回看这一题的概念Revisit this concept

第 2 题 · 参考回答Question 2 · Reference answer

分块决定一次取回的信息单元；嵌入决定文本的向量表示。先查答案所在块是否进入候选，再检查排序与生成，避免把检索问题误当成生成问题。Chunking defines retrieval units; embedding represents text as vectors. Check whether the answer-bearing chunk reaches candidates before investigating ranking and generation.

第 3 题 · 参考回答Question 3 · Reference answer

执行端校验工具名称、参数与授权范围；把检索内容和工具结果作为不可信数据处理。涉及写入或外部影响的动作，按业务风险设置审批与可撤回方式。Validate tool names, arguments and authorization at execution. Treat retrieved text and tool results as untrusted data. Add approval and recovery according to the risk of writes or external effects.

回看这一题的概念Revisit this concept

第 4 题 · 参考回答Question 4 · Reference answer

兼容的是请求/响应形状与常见字段，便于换 base URL；模型名、流式细节、工具调用格式、计费和限流仍各不同。上线前要用同一组请求做对照。It standardises request/response shapes and common fields so the base URL can change; model names, streaming details, tool-call formats, billing and rate limits still differ. Compare with the same request set before launch.

第 5 题 · 参考回答Question 5 · Reference answer

先确认答案所在块是否被切碎或根本没入库，再查召回候选与排序，最后才换嵌入模型。分块和元数据错误换模型也救不回来。First check whether the answer-bearing chunk was split or never indexed, then inspect candidates and ranking, and only then swap the embedding model. Chunking and metadata errors will not be fixed by a new model.

回看这一题的概念Revisit this concept

第 6 题 · 参考回答Question 6 · Reference answer

它把外部资料放进上下文，缓解知识截止和来源缺失；不能保证检索到正确段落，也不能消除模型误读、冲突信息或引用错误。仍要评测命中与引用。It puts external material into context, easing knowledge cutoffs and missing sources; it cannot guarantee the right passage is retrieved, nor remove misreading, conflicting evidence or bad citations. Evaluate hits and citations.

回看这一题的概念Revisit this concept

第 7 题 · 参考回答Question 7 · Reference answer

工具定义由应用提供给模型，说明名称、参数和用途；工具调用由模型提出，执行端负责校验与授权。模型提议不等于可以执行。The application defines tools for the model, including names, arguments and purpose; the model proposes calls, while the execution layer validates and authorises. A proposal is not permission to execute.

回看这一题的概念Revisit this concept

第 8 题 · 参考回答Question 8 · Reference answer

它主要统一模型与工具/资源之间的发现和调用协议，降低接入成本；权限、审计和副作用仍由执行端与业务系统负责。不要把协议当成授权。It mainly standardises discovery and invocation between models and tools/resources, lowering integration cost; permissions, audit and side effects remain with the execution layer and business systems. A protocol is not authorisation.

回看这一题的概念Revisit this concept

第 9 题 · 参考回答Question 9 · Reference answer

工作流把步骤和分支预先写死，模型只在节点内生成；Agent 让模型决定下一步与工具。前者可预测、易审计，后者灵活但需要更强的护栏与回滚。A workflow fixes steps and branches in advance, with the model generating inside nodes; an agent lets the model choose the next step and tool. Workflows are predictable and auditable; agents are flexible but need stronger guardrails and rollback.

回看这一题的概念Revisit this concept

第 10 题 · 参考回答Question 10 · Reference answer

常见成功样本、边界/歧义样本、应当拒答或转人工的样本。三类都要有真实输入与判定标准；只有成功样本会掩盖失败。Typical success cases, boundary/ambiguous cases, and cases that should be refused or escalated. Each needs real inputs and a rubric; success-only sets hide failure.
