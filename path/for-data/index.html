数据与 RAG 路线The Data & RAG Route

进阶Builder看得懂概念，开始动手做Know the basics and start building

约 50 分钟about 50 minutes

数据从哪来、能不能用、怎么切、怎么测。读完能搭一条最小可评测的 RAG 语料，而不是把文档一股脑丢进向量库。Where data comes from, whether it is usable, how to chunk it and how to test it. Finish with a minimum evaluable RAG corpus, not a pile of PDFs in a vector store.

按这个顺序读Read in this order
  1. 数据授权Data licensing
  2. 训练数据溯源Training data provenance
  3. 训练集与测试集Training Set, Test Set
  4. 数据污染Data Contamination
  5. 分块Chunking
  6. 混合检索Hybrid retrieval
  7. 检索质量度量Retrieval Quality Metrics
  8. 怎么用 AI 清洗数据How to clean data with AI
  9. 怎么给数据集写数据卡How to write a dataset card
  10. 怎么用 AI 搭 RAG 语料How to build a RAG corpus with AI
学完自测Checkpoint
  1. 拿到一份数据集，能列出至少三项必须核对的授权信息
  2. 说清「按固定字数切」和「按语义结构切」各自会在什么问题上失效
  3. 用 10 个真实问题跑一次检索，记录命中率、引用准确率和拒答率
  4. 数据卡里为什么必须写「不适用场景」？
  5. RAG 语料去重与保留版本，哪个优先？
  6. 清洗规则写在代码里还是数据卡里？
  7. 标注一致性低，先改指南还是先换标注员？
  8. 训练集/验证集切分，最常见的泄漏是什么？
  9. 合成数据能解决什么，不能解决什么？
  10. 一个数据集要交付，最少附带哪四份东西？
  1. Given a dataset, list at least three licence facts that must be checked
  2. Explain when fixed-length chunking and semantic chunking each fail
  3. Run 10 real questions through retrieval and record hit rate, citation accuracy and refusal rate
  4. Why must a data card state “not suitable for” scenarios?
  5. In RAG corpora, deduplication or version retention first?
  6. Should cleaning rules live in code or in the data card?
  7. When inter-annotator agreement is low, revise the guideline or replace annotators first?
  8. What is the most common leakage when splitting train and validation sets?
  9. What can synthetic data solve, and what can it not?
  10. What four items should a dataset delivery include at minimum?

先试着回答，再展开参考答案。答不上来的地方，可从上方步骤返回对应词条。参考回答是核对要点，不要求逐字复述。Try answering before opening the reference. Revisit the relevant step above if needed. These answers highlight key ideas; you do not need to repeat the wording.

第 1 题 · 参考回答Question 1 · Reference answer

许可证类型、商用/再分发/衍生作品条款、地域与期限、是否含个人数据、原始来源能否追溯。Licence type, commercial/redistribution/derivative terms, territory and term, whether personal data is included, and whether the original source is traceable.

回看这一题的概念Revisit this concept

第 2 题 · 参考回答Question 2 · Reference answer

固定字数会把一个条件切成两半，答案缺上下文；语义切分遇到格式混乱、无标题的文档会切得太碎或太大。Fixed length splits a condition in half and removes context; semantic chunking over-splits or over-merges messy documents without headings.

回看这一题的概念Revisit this concept

第 3 题 · 参考回答Question 3 · Reference answer

命中率看正确文档是否进前 k；引用准确率看答案是否引对原文；拒答率看无依据时是否说不知道。Hit rate: does the right document enter top-k; citation accuracy: does the answer cite the right passage; refusal rate: does it say “I don’t know” without evidence.

回看这一题的概念Revisit this concept

第 4 题 · 参考回答Question 4 · Reference answer

数据卡不只说明能做什么，还要防止把数据用到未覆盖的人群、语言、时间或任务。没有不适用场景，使用者会默认它通用。A data card should not only say what the data supports; it must prevent use on uncovered populations, languages, periods or tasks. Without exclusions, users assume general applicability.

回看这一题的概念Revisit this concept

第 5 题 · 参考回答Question 5 · Reference answer

先保留权威版本与版本关系，再做去重；否则会把新旧版本混成一段，检索到过期条款。去重要保留来源与时间，不能只留最短文本。Keep the authoritative version and version links first, then deduplicate; otherwise old and new clauses blend and retrieval returns stale text. Dedup must retain source and date, not just the shortest passage.

回看这一题的概念Revisit this concept

第 6 题 · 参考回答Question 6 · Reference answer

两边都要：代码可执行、可复跑；数据卡解释规则、影响与未处理项。只写代码，使用者不知道删了什么；只写卡，无法复现。Both: code makes rules executable and reproducible; the data card explains rules, effects and unresolved items. Code alone hides what was removed; a card alone cannot reproduce it.

回看这一题的概念Revisit this concept

第 7 题 · 参考回答Question 7 · Reference answer

先查指南是否对边界案例有定义、培训是否一致，再查标注员是否按同一判法。直接换人会重复同样的歧义，且丢失已发现的边界案例。First check whether the guideline defines boundary cases and training was consistent, then whether annotators applied the same rubric. Replacing people repeats the ambiguity and loses the discovered edge cases.

回看这一题的概念Revisit this concept

第 8 题 · 参考回答Question 8 · Reference answer

同一用户、同一文档或同一近重复样本跨集合；时间序列还会用未来预测过去。按实体/时间分组切分，并做近重复检查。The same user, document or near-duplicate appears across splits; time series also use the future to predict the past. Split by entity/time and run near-duplicate checks.

回看这一题的概念Revisit this concept

第 9 题 · 参考回答Question 9 · Reference answer

它能补稀少场景、隐私受限样本和格式变体；不能替代真实分布，也可能放大生成器的偏差。合成数据要标来源、比例，并用真实集验证。It can add rare scenarios, privacy-limited samples and format variants; it cannot replace the real distribution and may amplify generator bias. Label source and proportion, and validate on real data.

回看这一题的概念Revisit this concept

第 10 题 · 参考回答Question 10 · Reference answer

数据卡、字段说明与许可、切分与版本、质量/已知缺口记录。四份缺一，接收方就无法判断能不能用、怎么复现。A data card, field descriptions and licence, split and version, and quality/known-gap record. Missing one leaves the recipient unable to judge usability or reproduce.

走完这一段，去哪练Where to practise after this route

这条路线负责把概念讲通。下一步不用再读一遍；挑一个地方，把刚学的用一次。This route gets the concepts across. Do not reread it; pick one place below and use what you just learned once.

按任务找工具，查许可和部署Find a tool by task, check licence and deployment

先按手里的活筛，再看它跑在哪、许可能不能商用、数据去哪里。Filter by the job first, then check where it runs, whether the licence allows commercial use, and where data goes.

从源码跑一个最小项目Run a minimal project from source

选一个许可清楚的仓库，先跑通最小例子，再决定要不要接进自己的流程。Pick a repo with a clear licence, get the smallest example running, then decide whether to integrate it.

拿原始 prompt 复跑一件作品Reproduce a piece from its original prompt

只改一个变量，看看结果差在哪里；别把一次复跑当成模型结论。Change one variable and see what differs. Do not treat one rerun as a conclusion about the model.
