学完自测Checkpoint
  1. 拿到一个新模型的介绍页，能列出该问的问题：能力、边界、成本、许可、锁定
  2. 判断一件事该用 API 还是本地跑，并说出判断依据
  3. 看懂一份基准榜单，并说出它至少一处代表不了你的实际效果
  1. Given a new model's page, list the questions to ask: capability, limits, cost, licence, lock-in
  2. Decide API or local for a given job, and state the reasoning
  3. Read a benchmark table and name at least one thing it cannot say about your actual use

第 1 题 · 参考回答Question 1 · Reference answer

先写任务和验收条件，再查能力限制、数据去向、总成本、许可证、导出与迁移方式。不能用一个榜单名次替代这些问题。Define the task and acceptance criteria, then check limits, data handling, total cost, licensing, export and migration. A leaderboard position cannot answer these questions.

第 2 题 · 参考回答Question 2 · Reference answer

示例：低频且无部署经验的任务可先评估 API；不能把数据交给外部服务时，应评估符合约束的本地或私有方案。两边都要核算成本、质量、维护和硬件限制。For example, assess an API for occasional work without deployment expertise; assess a suitable local/private option when external data transfer is disallowed. Compare cost, quality, maintenance and hardware limits in both cases.

第 3 题 · 参考回答Question 3 · Reference answer

核对基准版本、输入、工具与评分口径；它未必覆盖你的中文材料、长文档、响应时间或失败成本。用自己的代表性任务补足缺口。Check benchmark version, inputs, tools and scoring. It may omit your Chinese documents, long inputs, latency requirements or cost of failure. Add representative tasks of your own.
